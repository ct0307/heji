# 恢复余额守恒查询优化验收

日期：2026-11-19。余额核验已改为按账本/成员预聚合；既有004恢复库只读查询实测10.4487秒，全部财务检查保留。未重跑迁移、备份、恢复或负载，未清库。完整恢复历史结果仍为41分20.52秒、30分钟目标未通过；本轮不能关闭该目标或M4。

## 原因与方案

旧查询从300名成员出发，分别执行垫付、份额、确认转出、确认转入4个相关子查询。[原MySQL计划](evidence/m4-restore-004-query-plan-2026-11-19T10-38-38-791Z.json)标记4个dependent=true/cacheable=false，其中版本访问按bookId重复进行，行数估计偏低。[慢查询观察](evidence/m4-restore-004-slow-query-2026-11-19.json)证明当时该语句已执行1321秒，但不是最终耗时；本轮没有再次运行原慢查询。

推荐并落实：四类事实分别按bookId/memberId聚合，再从全部book_members LEFT JOIN，最后逐账本SUM(balanceFen)核验。每个聚合关系每成员最多一行，避免多事实直接连接导致金额倍增。MySQL可合并active_expenses CTE，因此不承诺只扫描版本一次；新计划实际为垫付与份额各自遍历版本，但不再按300成员重复执行。

未选择索引/统计调参：需数据库变更且不能直接消除相关结构；未选择仅将支出总额与份额总额相减：会弱化成员关联核验。没有调整索引、ANALYZE、优化器会话开关或001–004源SQL。

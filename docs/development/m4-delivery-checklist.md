## 三、10分钟演示步骤

以下是待现场执行的脚本，未在本轮创建账号或账本。使用两个隔离浏览器会话A/B及一个全新虚构账本；普通两个标签共享登录，不能当作两账号。所有金额用元显示，接口用整数分字符串。先检查5174/3001端口，已有无关进程不得停止。演示需使用已迁移开发库，不能运行seed、迁移、恢复或压力测试来准备演示。

| 时间 | 操作 | 必须观察的结果 |
|---|---|---|
| 0–1分钟 | A登录并建虚构账本，邀请B加入；展示非成员访问控制的已有测试证据 | A/B成员身份正确，邀请明文不进入录屏或抓包截图 |
| 1–2分钟 | A在“明细”录入100.00元，A垫付，A/B均分 | A应收50.00，B应付50.00；消费100.00，垫付和承担分别展示 |
| 2–3分钟 | B在“结算”登记已转给A的50.00元 | 只有待确认登记，余额仍为A应收50.00、B应付50.00；建议不是付款 |
| 3–4分钟 | A打开该登记的“核对并预览”，先不勾选；B再录入2.00元、A垫付、A/B均分 | 当前余额变为A应收51.00、B应付51.00；A的旧预览已过期 |
| 4–5分钟 | A勾选并点击旧预览确认 | 返回409/PREVIEW_STALE；只读取一次新预览，清除旧勾选，不自动POST重试。新预览显示确认后A应收1.00、B应付1.00 |
| 5–6分钟 | 暂停人工录入，A重新核对、勾选并确认；B再登记1.00元，A按新预览确认 | 每次成功仅入账一条；两次确认合计51.00元，A/B余额归零，消费仍为102.00元 |
| 6–7分钟 | 展示一个“100.01元均分”独立虚构示例；随后查看统计 | 两份额为50.01/50.00，尾差按固定成员ID排序，不按昵称或录入顺序；转账不计消费。此示例不与前述余额计算混用 |
| 7–8分钟 | 两会话查看同一账本；一方录入，另一方保留未提交草稿观察更新 | 草稿不丢失；断线重连和补查可展示M3已有证据，新的现场断线操作另行安排，不结束无关服务 |
| 8–9分钟 | 展示条件更新、幂等、100并发单入账和冲正的既有测试 | 缺If-Match为428、过期为412；幂等重放不新增。冲正是保留原记录的反向事实，不代表真实退款 |
| 9–10分钟 | 打开M4报告与正式JSON摘要，说明性能、恢复及限制 | 读写时延本机达标；热点0/3364、分散4259/4259分别说明；003历史4802850行/807.15秒，旧004为2480.52秒失败、新timed目标6609958行/503.96秒通过；Word仍为历史版，公网/生产未验收 |

手工暂停录入仅用于展示正常确认路径，不是服务端锁定写入的功能，也不是热点P1修复。若确认再次过期，保持现有刷新和重新确认流程；不得静默替换版本或把冲突计为成功。现场未成功的步骤按实际记录，不能借用历史截图声称本次已通过。

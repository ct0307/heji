# 短时结算窗口热点确认负载验收设计

短时结算窗口已在heji_dev完成004迁移、真实多连接测试及主要UI验收；`heji_m4_bench`的004迁移也已在此前独立许可下完成。窗口固定30秒、结束后冷却30秒；绑定确认需要有效成员、请求revision、financialVersion、windowId和未到期窗口。窗口期间其他财务写入预期返回409/SETTLEMENT_WINDOW_ACTIVE。新负载只读核对004 checksum，不执行迁移。

## 目标

在当前20用户热点场景下，验证人工等待期间窗口确实保持绑定确认可用，同时可靠拦截旁路财务写入；验证窗口自然到期后普通写入恢复。保留全部服务端授权、请求版本及财务版本校验，确认不得自动化或代替用户。

本验收只对当前固定基准库、负载与记录的本机环境给结论，不外推其他硬件或生产环境。

## 范围与隔离

- 唯一负载库为现有`heji_m4_bench`，复用当前隔离种子和30成员同账本场景，不清库、不重种子、不覆盖历史证据。
- bench 004结构已存在；每次真实负载开始前只读核对目标、夹具和004 checksum。禁止重跑迁移。
- 负载开始前须另获真实负载及数据写入许可。只能使用本地M4固定隔离目标，不连接heji_dev、恢复库、外部服务或公网。
- 新建独立runId与证据文件，禁止续跑或重跑旧正式基准和参与范围研究。
- 每次有效确认都会增加隔离转账/审计事实；数据增长、失败残留及其保留策略在许可中明确，测试后不清理。

## 负载模型

新增独立`window-benchmark`入口和隔离实现，不改变旧benchmark参数、正式12组口径或窗口业务规则。使用20个已授权虚构成员会话围绕一个热点账本：1名窗口持有者、19名旁路写入者。每个采样先准备新的待确认请求、申请窗口并取得同事务的新预览；持有者按配置等待，不发起确认之前不自动刷新、续期或关闭窗口。等待期间旁路用户以每用户不超过1次/秒尝试新增小额支出；有效窗口内这些操作必须受到服务端保护并返回预期409，不形成支出、审计或幂等成功事实。等待结束后持有者提交窗口ID、新预览financialVersion和请求revision，只确认一次。

等待档为5秒、15秒、25秒，每档60个完整工作流，顺序执行，采样间遵守30秒冷却。每档预计约35、45、55分钟，总负载约135分钟，外加准备、冷却核对和报告开销。每档至少57/60成功，对应观测成功率不低于95%；样本比例不作为广泛SLA或跨环境置信结论。

另作一次自然到期边界检查：不确认，等待窗口超过30秒；旧windowId确认必须返回SETTLEMENT_WINDOW_EXPIRED，普通财务写入在到期后恢复成功，窗口冷却不得阻断普通写入。此边界样本不计入三档成功率。

## 验收指标

| 指标 | 通过条件 | 计数规则 |
|---|---|---|
| 窗口申请及绑定确认 | 每档至少57/60条工作流成功，且确认主体和绑定请求正确 | 申请失败、到期、过期、版本/请求不匹配及未能提交均计失败；无自动重试 |
| 窗口内旁路写保护 | 100%返回409/SETTLEMENT_WINDOW_ACTIVE | 仅在数据库确认窗口有效的采样窗口期内统计；不得产生支出/转账/审计/成功幂等记录 |
| 确认HTTP时延 | P95不超过800ms | 从确认POST开始到响应；不含5/15/25秒人工思考时间 |
| 其他写入与窗口申请HTTP时延 | 各类P95不超过800ms | 预期409也计入时延，不算系统故障 |
| 系统故障 | 0次网络/响应故障、5xx或非预期状态 | 预期SETTLEMENT_WINDOW_ACTIVE、冷却拒绝及指定到期错误按场景单列，不混入5xx |
| 财务完整性 | 每个工作流仅一次确认入账，版本/请求revision/余额守恒，窗口按规则结束 | 确认幂等重放不得重复入账；阻止的旁路写不得改变事实 |
| 到期恢复 | 到期确认被拒，窗口外财务写入成功 | 必须来自独立确认的数据库时钟边界，不依赖客户端倒计时 |

完整性指标优先于延迟和成功率；任何财务不一致、越权成功或重复入账均判该轮失败，不因其他指标达标而放行。

## 实施和执行顺序

1. 审核本设计和样本量，确认成功率/HTTP目标及负载范围；bench 004迁移已按先前独立许可完成，不在本流程重跑。
2. 生成独立实现计划；先写离线回归，再实现新负载入口。测试检查门禁、超时与请求分类、窗口等待/到期、数据计数、原始旧基准参数不变和脱敏输出；运行完整测试、类型检查与构建。
3. 负载入口只读预检固定bench夹具、004 checksum、完整表计数、全账本财务版本摘要，并要求其他连接、活动窗口和冷却窗口均为0；不自动停止进程、不重种子。
4. 取得覆盖20虚拟用户、热点账本、三档各60次、约135分钟和数据保留的明确负载/写入许可后，执行一次新run；全程不重试或自动续跑。
5. 独立只读复核结束计数/财务摘要/窗口状态和工作流证据，分别判定每档可用性、HTTP延迟、服务错误与财务完整性。

## 设计自审

- 30秒窗口内等待25秒后再提交留有真实边界压力；另以独立自然到期场景验证普通写恢复。
- 预期409从系统故障率中分离，但仍纳入HTTP时延和旁路保护完整性。
- 样本成功率不放宽全账本financialVersion保护；失败不会自动获取新预览或再次确认。
- bench迁移已经完成；新负载写入和已有数据保留范围另行授权。不使用恢复库，不清理或覆盖历史证据。
- 60次/档预计运行时间长，按每档统计原始样本，任一档失败都保留实际结果，不把其他等待档平均后掩盖退化。

## 验收步骤

| 优先级 | 场景 | 必须看到的结果 |
|---|---|---|
| P1 | 普通GET预览 | 不自动申请窗口；原financialVersion和revision保持完整门禁 |
| P1 | 显式申请窗口 | 提示暂停同账本其他财务写入30秒；返回新预览后旧勾选清除，倒计时出现；不自动勾选或确认 |
| P1 | 人工确认 | 重新核对、勾选、点击；只有一次确认POST，含两版本和expectedWindowId；余额结清，窗口关闭 |
| P1 | 另一个会话写入受阻 | 409窗口占用提示可读，支出/转账草稿及原幂等意图保留，没有自动POST循环；窗口结束后用户可显式重试 |
| P1 | 创建者关闭他人窗口 | 乙持有并勾选，甲主动关闭；乙切到明细再返回结算，立刻清勾选、禁用并补查，旧窗口不能继续确认 |
| P1 | 自然到期和冷却 | 实际等待到期，勾选清除、确认禁用；普通写入恢复；冷却内申请明确提示剩余时间，不自动申请或回退确认 |
| P1 | 申请响应丢失 | 服务端已创建但客户端未收到响应时，客户端禁止确认；显式重试使用原键得到原ID/期限，不续期、不创建第二窗口 |
| P1 | 确认响应丢失 | 不自动再次POST；显式核对原请求结果、重新鉴权的重放不新增转账；UI不能把未收到响应冒充失败付款 |
| P1 | 状态读取断网 | 清勾选并禁用窗口确认，输入保留；恢复网络后由明确状态补查恢复，不替用户勾选 |
| P1 | 刷新、跨标签及重复点击 | 不自动续租/确认；旧ID不能关闭后续窗口，同一意图不并行重复提交 |
| P2 | 空请求与手机布局 | 无待确认请求时显示真实空状态；360/390/768/1440宽度无横向溢出、控件可点击、提示不被截断 |
| P2 | 页面与控制台 | 正确页面标题、内容非空、无框架错误遮罩；相关控制台异常逐项解释，保留脱敏截图和请求计数 |

网络模拟只记录请求路径、方法、状态码、次数及必要的版本/windowId对照，不记录完整请求头、Cookie、CSRF、密码、邀请明文或整个HTTP正文。不得用修改真实DOM的方式伪造成功或可用状态。

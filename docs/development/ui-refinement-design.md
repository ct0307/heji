# 双界面视觉精修设计

日期：2026-11-19。用户在明确视觉问题后要求“设计方案并落实完成”，本轮覆盖方案、正式前端实现和隔离浏览器验收；沿用已确认的 A 默认、B 可选及 B 墨蓝灰无衬线方向。

## 目标与取舍

产品是供朋友、合租成员共同记录垫付与分摊的“合记”。账本首屏应让人迅速看清个人应收/应付、待核对事项和实际开销，并能直接记账。

比较三种处理：仅调整颜色字号成本低但不能解决首屏比例；整套改为新的仪表盘会破坏用户已选布局且需要额外数据；保留双布局并重排视觉层级能直接处理当前问题。本轮采用第三种。

## 视觉系统

| 项目 | A 雾青工作台 | B 墨蓝账页 |
| --- | --- | --- |
| 结构 | 雾青侧栏、横向收付概览、明细工作区 | 轻顶栏、左账页、右侧收付摘要 |
| 背景 | 雾青纸色 #F3F6F3 | 冷灰纸色 #F3F5F7 |
| 内容面 | 白色 #FFFFFF | 白色 #FFFFFF |
| 主强调 | 墨绿 #284E40 | 墨蓝灰 #40566E |
| 主文字 | #20342B | #263647 |
| 细线 | 柔和青灰 #DEE6DE | 低饱和蓝灰，保持可辨识 |
| 特征 | 协作侧栏、个人收付的绿色重心 | 清晰账页、日期纵线、收付摘要细线 |

中文采用系统无衬线栈；标题采用等线/微软雅黑UI，正文优先苹方/微软雅黑UI，金额使用 Segoe UI 与等宽数字特性。标题约28–32px、正文14–15px、辅助12–13px、文字操作14px、主金额40–44px。最终值以实际字体、对比度和手机检查校准。仅使用已有系统字体，不请求外部字体或安装依赖。

间距采用4/8/12/16/24/32尺度。强调色用于主操作、当前导航和关键金额；错误、危险、未确认提示保留各自语义。去除原 B 的明亮蓝紫，减少边框与整片空白，不引入与账务无关的插画、装饰数字、虚构趋势。

## 页面与交互

1. 压缩账本返回区与页头，保留清晰标题和成员信息。唯一新建主入口为页头“＋ 记一笔”，移除明细区重复的“新增开销”。新建后聚焦金额，不提交数据。
2. 分类/日期筛选放入默认关闭的原生 `details.expense-filter-disclosure`，展开后原标签和表单继续可用。已应用条件明确显示；开合或切换界面不清空筛选输入。桌面展开时尽量同一行，手机自然折行。
3. 明细条目保留真实日期、用途、分类、垫付人/录入人、金额及详情。金额对齐，分类成为轻量检索线索。首屏优先显示实际账目。
4. A 保留清晰绿色个人收付，B 通过账页和右侧摘要形成独立阅读节奏。结算收据、统计和成员使用同一文字/间距系统；长金额和长名称正常换行。
5. 统一“合记”标识，在公共页与登录后页使用同一可复用 SVG。图形表达两张账页相合，只有装饰作用，不替代可访问的品牌文字。
6. 界面设置用小型布局示意替代单纯色块，让用户理解两种布局；选项仍用原生 radio，默认 A、即时切换、当前浏览器记忆、保存失败提示、Escape及焦点恢复均保留。

## 架构与边界

App 继续唯一 RouterView；BookView 保留 book.id key 和四面板 v-show。主题只改变根 data-interface，不能重建业务组件、清除草稿或确认勾选。API、财务版本、短时窗口和服务端授权规则均不改。已归档账本不可新增的门禁保留。

只涉及正式 apps/web、隔离 tests/web 和开发记录，保留所有旧原型及旧证据。无依赖安装、真实账号/账本/财务写入、数据库迁移、新负载、恢复、部署或系统配置；热点 P1、004 恢复和新负载仍按原状态处理。

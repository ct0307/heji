# 项目启动准备发现

## 项目现状

- 项目根目录目前包含《多人共享账本与费用分摊系统_设计文档_v1.0.docx》、`.superpowers/` 草图产物、`work/ui-design/` 设计记录和 `work/project-kickoff/` 启动准备记录。
- 当前没有业务源码、`package.json`、锁文件、项目根级 AGENTS.md 或 `.git`；`git status` 因当前目录尚未初始化为 Git 仓库而无法运行，这是目录现状，不是代码错误。
- UI 草图是独立 HTML 和模拟数据原型，不是正式业务页面，也没有前后端服务。

## 已有设计基线

- 选题：基于 Vue 3 与 Node.js 的多人共享账本与费用分摊系统。
- 实施技术基线：Vue 3、TypeScript、Vite、Element Plus、Node.js 24.x、Express 5、MySQL 8.0.18+、Nginx、WebSocket。按用户最新指示采用设计文档默认方案；具体依赖版本和实际环境在初始化时核验。
- 业务核心：账本作为成员权限边界；支出分摊与线下转账分开记录；待确认转账不改变余额；金额以分为单位精确计算；录入人和实际付款人分别记录。
- 已核对的示例：三笔支出 1260、368、96 元，总额 1724 元；三人承担 580、572、572 元；余额分别为 +680、-204、-476 元，合计为 0。
- 现有草图已覆盖账本总览、记账、待确认转账、明细等主要交互，并做过桌面/手机视口和空状态检查；不代表 API、数据库或业务安全已实现。

## 发现的优先级不一致

上一轮答复把 WebSocket、Nginx 和 SQL 实验概括成“有余力再做”，但设计文档第 2 章将相关 FR-15/FR-16 标为 P1，第 15 章也将它们作为课程主线。当前启动计划以设计文档为准；只有评分细则或用户确认后才调整优先级。

## 建议的实施阶段

1. **环境与项目骨架**：按设计技术栈核验运行环境，初始化 Git 与项目说明，建立前后端最小可运行骨架和健康检查。
2. **身份与账本权限**：注册/登录/注销、账本创建、成员邀请/加入、服务端授权和跨账本隔离。
3. **支出与余额**：支出新增/编辑/作废、均分与指定金额、整数分计算、当前净余额与基本统计。
4. **转账闭环**：转账登记、收款方确认/拒绝、取消、错误确认冲正、审计记录和并发/幂等保护。
5. **课程技术证据与发布**：按设计第 15 章补齐 WebSocket、Nginx、MySQL 查询实验的验收证据，完成部署/恢复演练和答辩材料。

阶段 2 至 4 按端到端切片迭代：每个切片同时包含页面、API、数据库变更和测试，避免最后才联调。按依赖顺序推进，无需先确定日历工期。

## 验收基线

- 金额算法有独立测试，含不能整除尾差、指定金额和不守恒拒绝。
- 未确认转账不改变余额；确认后余额变化方向和金额正确。
- 非成员不能跨账本读取或写入；录入人与付款人权限/身份不混淆。
- 错误状态、空数据、移动端关键流程纳入验收。
- 部署、性能或恢复能力只按实际执行证据报告，不以设计目标代替测试结果。

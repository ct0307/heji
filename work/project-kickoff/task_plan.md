# 项目启动准备计划

## 目标

把现有产品设计整理成开始编码前可核对的启动包：明确项目现状、设计基线、待确认事项、实现阶段和验收门槛。本阶段不创建业务代码、不安装依赖、不初始化 Git、不部署。

## 阶段

| 阶段 | 状态 | 结果 |
|---|---|---|
| 1. 盘点现有项目与设计材料 | 已完成 | 确认设计文档、UI 草图和目录状态 |
| 2. 审查开工前缺项与范围风险 | 已完成 | 标记课程约束、环境核验及 P1 范围风险 |
| 3. 编写启动准备包 | 已完成 | 形成发现记录、启动清单和分阶段实施顺序 |
| 4. 确认实施基线 | 已完成 | 用户明确不以提交日期、评分细则和课程技术限制为前提，直接依据设计文档推进 |
| 5. 项目初始化与首个纵向切片 | 可开始，尚未实施 | 按设计第 13 章 M1 起步；环境检查和工程配置在实施中完成 |

## 决策边界

- 按用户最新指示，采用《多人共享账本与费用分摊系统_设计文档_v1.0.docx》的技术和范围作为实施基线，无需等待外部课程条件。
- 保留设计文档中的 P1，包括 REST API、MySQL 事务/分析、Nginx 和 WebSocket；P2/P3 不抢占核心闭环的实现顺序。
- 已核验本机 Node.js v24.14.1、npm 11.11.0；MySQL、Nginx 和依赖兼容性随对应实施阶段检查，不将尚未核验写成已可用。
- 首个功能验收切片建议为：注册/登录 → 创建账本并加入成员 → 录入支出与分摊 → 查看净余额 → 登记并确认转账。
- 项目级 AGENTS.md、依赖清单、环境变量示例和 Git 初始化应在首个编码阶段开始前落实；当前不安装外部依赖。

## 完成标准

- 准备材料与设计文档一致，未把建议默认值写成已核实事实。
- 清楚区分核心业务闭环、课程技术证据和后续增强。
- 每个开工前待确认项都有负责人/证据或明确的建议默认值。
- 启动清单不包含真实密钥、密码或私人账本数据。

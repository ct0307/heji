# 合记 UI 最终推荐方案

日期：2026-11-17。性质：基于现有设计基线的综合推荐，供后续实现采用和用户审阅；并不把本次推荐写成用户已经批准。

## 结论

采用 A 的统一协作框架、B 的日期分组明细、C 的按需核账能力。主入口固定为「总览／开销明细／结算与确认」，统计和操作记录保留次级入口。首页只呈现当前金额、待办与少量最近消费，完整明细和完整成员收支各有专属页面。

## 三套方案的取舍

| 方向 | 优势 | 问题 | 最终处理 |
|---|---|---|---|
| A 协作工作台 | 记账、核对入口直接；导航适合完整应用；任务状态容易识别 | 旧稿把当前应收放到右侧，手机排在开销之后；长期没有待办时主区容易空 | 保留应用框架和核对流程；首页恢复「金额→待办→最近开销」，待办采用紧凑摘要 |
| B 行程账本 | 按日期回忆和补录消费自然；条目能清楚展示谁付、谁记；手机单列容易适配 | 时间线长，不能承担整个系统首页；过度使用旅行语言不适合合租等场景 | 用作开销明细，增加搜索和日期筛选；产品文案统一使用账本、开销与成员 |
| C 对账工作区 | 成员金额组成、付款人/录入人和分摊清楚；明细与详情同屏方便核对 | 首页密度大；固定检查区占用空间；手机宽表横滚负担高 | 成员收支放结算页；明细选中后才打开检查区；手机用详情弹层与可展开成员卡片 |

以上是针对当前草图和设计目标的产品判断，没有用户访谈、真实使用日志或耗时实验，不将偏好写成研究结论，也不虚构评分。

## 页面与信息优先级

### 总览

1. 首屏先显示「你当前应收／应付」，零余额与空账本分别表述，不能把没有开销说成已经结清。
2. 显示共同消费、本人垫付和本人承担，三个数字分别命名，不与当前净额混为一谈。
3. 金额下方紧邻待确认摘要，说明金额尚未抵减余额；核对操作经预览和勾选确认。
4. 下面显示最近最多五笔有效开销，提供进入完整明细的入口。当前样本只有三笔，不为填充页面制造数据。
5. 桌面可附带紧凑成员净额摘要；手机将其置于主要任务之后。首页不展开完整收支表、完整时间线或固定检查区。

### 开销明细

- 日期倒序分组，显示日期小计；搜索名称、分类、付款人或录入人，并可按发生日期筛选。
- 日期筛选只影响明细和筛选合计，不改变当前账本余额。
- 付款人与录入人相同时简化文案，不同时明确分别显示。
- 宽屏点选记录后才展开侧边检查区；窄屏和手机打开详情弹层。没有选中时完整利用列表宽度。
- 没有匹配项时说明原因，并提供清除筛选入口。

### 结算与确认

- 集中展示各成员的垫付、承担、已确认收付与当前净额，保留固定金额口径。
- 待确认登记与结算建议分开呈现；建议不能被当作已经付款，也不提供「一键清账」。
- 手机用成员摘要加展开明细，避免横滚表格成为主要路径。
- 未确认、确认、冲正、拒绝等状态和授权在正式实施中按原设计落实；当前草图只演示一笔待收登记的模拟确认。

### 次级页面

- 统计分析保留分类消费汇总；转账与冲正不计入消费。
- 操作记录保留可追溯事实；当前草图在模拟确认后同步更新记录。
- 邀请、成员生命周期、归档、WebSocket、Nginx 及 SQL 实验等仍属于原设计范围，本次 UI 综合不降级或移除 P1。

## 视觉与响应式

- 保持品牌蓝 `#2563b9`、深色正文 `#182a40`、浅灰蓝背景 `#f3f6fa` 与轻分隔；颜色只承担品牌、选择与状态，不单靠颜色表达收付方向。
- 标题 24–28px，正文 14–16px，辅助文字以 12px 为基准；金额使用等宽数字。
- 桌面采用统一侧栏、面包屑和主按钮；手机采用总览、明细、结算加记账的快捷导航，统计与记录通过次级入口访问。
- 主要点击目标至少 44px；键盘焦点可见；弹层支持关闭和 Escape；减少动效设置生效。
- 默认不增加图表大屏、批量处理、双视图切换或真实支付，以免增加使用和实现成本。

## 原型边界与验收

- 综合稿以同一份页面内状态驱动总览、明细、结算、统计和记录，不再是互不相通的三个独立演示页面。
- 样本消费 1724 元；阿宁初始应收 680 元；待确认 204 元不抵减。模拟确认后应收 476 元，净额为 +476、0、−476，消费统计保持 1724 元。
- 记账弹层只用于分摊与流程预览，不保存新账目。没有业务后端、认证、持久化或真实资金操作。
- 检查正常数据、空账本、模拟断网、错误输入、筛选空结果、手机显示以及跨页面金额一致性。实际结果另记在验证记录中。

## 正式实现顺序

P1：统一应用框架和导航 → 金额、身份与权限契约 → 记账及分摊 → 明细与详情 → 转账确认及冲正 → 异常与手机验收。统计、历史及课程技术证据继续按原设计 M1–M4 进入相应阶段。

本轮解决 UI 综合决策，不新增依赖或修改正式业务技术栈；工程实现仍采用设计文档中的 Vue 3、TypeScript、Express 和 MySQL 方案。

# 合记：信息结构方向探索

## 本轮目标

用户指出旧稿 A/B/C 主要只有颜色区别。本轮统一品牌色，在同一份账务示例上比较三种导航、信息优先级与操作结构。输出为可点击的设计概念；正式业务页面尚未实施，方向尚待用户选择。

| 方向 | 首要问题 | 导航与结构 | 重点操作 |
|---|---|---|---|
| A 协作工作台 | 现在有什么需要我处理？ | 左侧账本导航，主区核对待办与最近开销，右侧个人余额与成员净额 | 从待办进入转账核对，从主按钮打开记账预览 |
| B 行程账本 | 哪一天发生了哪些共同消费？ | 顶部横向导航，日期时间线，侧边轻量结算摘要 | 按日期筛选、查看条目、随手记账 |
| C 对账工作区 | 每个人的金额和每笔费用是否对得上？ | 顶部工具条，成员收支对照表，明细表与同屏检查区 | 搜索明细、选择行核对付款人/录入人/分摊 |

## 共用视觉约束

- 品牌蓝 `#2563b9`，正文 `#182a40`，辅助 `#6a7a8c`，背景 `#f3f6fa`，分隔 `#e1e7ef`；状态色用于待确认和已确认，不混用应收应付含义。
- 中文优先 Microsoft YaHei UI；金额使用 Bahnschrift 和等宽数字。正文 14–16px，辅助文字以 12px 为基准。
- 导航、日期轨道、表格对应具体任务，不添加营销口号、虚构指标或真实支付入口。
- 手机重新组织布局；表格只在自身容器内滚动，页面整体不横向溢出。提供键盘焦点、原生弹层及减少动效支持。

## 财务口径

总消费 1724 元：民宿 1260 元，晚餐 368 元，打车 96 元。三人承担为 580、572、572 元，垫付为 1260、368、96 元，净额为 +680、-204、-476 元。

晚餐付款人是林悦，录入人是阿宁；页面分别显示。林悦登记向阿宁转账 204 元，待确认时不改变余额。模拟确认后净额为 +476、0、-476 元。三个方案分别维护自己的内存演示状态，重新加载恢复初始数据。

## 共享交互边界

- 记账：输入金额、选择成员、比较均分或指定金额，只做分摊预览，不保存账目。
- 核对：展示收付款人、金额和确认前后余额，经明确勾选后模拟确认；不涉及真实资金。
- 详情：展示三笔示例账目及分摊、付款人与录入人。
- B 的日期筛选和 C 的搜索、同屏详情由各方案独立实现。

## 工具限制

当前没有可用的内置图像生成工具。本轮以原生 HTML/CSS 呈现结构概念，不调用需要密钥的图像 API。不存在已批准的最终视觉图，不声称通过正式产品的图稿还原验收。
